# v1.0.1

一次以「少留痕迹」为主的更新：日志里不再出现凭据明文，首页也不再显示设备标识。推送链路本身没有改动。

> **适配范围**：本项目以 Pixel 设备为核心做适配与体验打磨。界面表现、保活行为、通知样式都只在 Pixel 上验证过，其他机型不保证效果。

## 亮点

### 修复：日志会把下行消息的解密密钥写成明文

这是本次发布最重要的一项。

**问题**：框架把小米推送的协议消息整段打进日志，其中**注册响应里带着 `regSecret`**——那是用来解密该应用全部下行消息的密钥，而且是明文。而这些日志在应用里可以一键打包导出，报 issue 时通常就是整份贴出去。

**修复**：在日志管道的出口加一层脱敏，**只替换值、保留键名与整行结构**，所以脱敏后的行仍然是可读的协议数据，形如 `"regSecret":"***"`。覆盖 `regSecret`／`regSec`／`security`／`token` 的各种前后缀／`password`／`pwd` 等凭据，兼容 JSON、XML 与 `key=value` 三种出现形态。

设备标识 `regId`／`devId` 不属于凭据，**仍然保留**——排障时要用它对上设备。

覆盖范围逐项核对过：logcat、应用日志文件（`cache/logs`，保留 7 天）、崩溃报告，以及经 Xposed 桥接过来的 SDK 日志，全部走同一条管道。

### 首页不再显示设备标识

仪表盘原先有两行 `devId`／`regId`。它们是设备级标识，对使用者没有可操作的信息量，而仪表盘是打开应用看到的第一屏。这两行去掉后，同组里补上「服务运行时长」，用来判断系统有没有频繁杀进程。

连接卡原先还带一行「已连接 X 秒」，与下方的服务运行时长计的是同一段时间，一并去掉。

## 安装

**覆盖安装即可，注册状态与推送记录都会保留。**

- 优先使用 **normal** 版本（`xmsf-v1.0.1-normal-release.apk`）
- 若你的系统（已知 COS）无法通过 bind 方式传递消息，改用 `xmsf-v1.0.1-vc105-release.apk`

> 如果你设备上装的不是本项目的签名（例如上游官方包），需要先卸载再安装，原有的注册列表与推送记录会被清除，各接入应用需要重新启动一次以完成注册。

## 已知问题

- 通知的时间戳沿用消息自身的时间，网络恢复后补收的旧消息会显示为旧时间
- 重连退避的上限为 5 分钟，极端情况下最长需要 5 分钟才会重新拨号
- 前台服务开关默认关闭

完整变更见 [提交历史](https://github.com/huaxianyan/PixelMiPushFramework/commits/master)。
