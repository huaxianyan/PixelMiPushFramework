# v1.0.0

Pixel MiPushFramework 以本项目名义发布的第一个版本。

本仓库 fork 自 [NihilityT/MiPushFramework](https://github.com/NihilityT/MiPushFramework)（GPL-3.0），此前没有发布过正式版本。**从这一版起启用独立版本线，不再沿用上游的 0.3.x 编号。**

## 亮点

### 修复：网络切换后长时间收不到推送

这是本次发布最重要的一项。

**症状**：WiFi 与移动数据互相切换之后，偶尔会长时间收不到任何推送。抓到的日志里，两段故障分别持续了 **1 小时 52 分**和 **10 分 35 秒**，期间 **52 次重连请求全部被丢弃**。

**根因**：连接状态机卡在 `connecting` 不放，后续所有重连都被它拒掉——日志原话是 `try to connect while connecting.`。触发条件是切换网络后留下的 TCP 黑洞：连接已经失效，但不会主动报错。

更隐蔽的一层：SDK 里**本来就带有连接超时看门狗**（`setConnectingTimeout()`），但整个 SDK 从未调用过它——扫描 758 个类，只找到声明和一处 `EnclosingMethod` 引用，没有任何 invoke 点。它是一段官方遗留的死代码。

**修复**：在状态机进入 `connecting` 时把看门狗武装起来，超时未连上就主动断开重连。只改了两个文件，不新增切面、不动 hook 模块。

**验证**：两次独立故障注入，看门狗分别在 48.02 s 与 47.28 s 切断僵死连接，之后 0.073 s 与 0.086 s 内重连成功，注入窗口内 `try to connect while connecting.` 出现 0 次。两次注入之间，连接连续近 20 小时没有中断。

### 界面现代化

全面转向 Material 3 与动态取色（Android 12+ 跟随系统壁纸）。原先新旧两套设计语言混用的问题一并清理。

- **新增仪表盘**，并作为启动页：连接状态、已注册应用数、上次接收时间、24 小时推送条数、XMPP 服务器、设备标识
- **推送记录改为两级页面**：一级按应用聚合、按最后一条消息的时间倒序，点进去才是该应用的完整记录
- **引导页重写为单页**：所有权限列在一页，每项各自跳转授权并即时回显状态，全部完成后点「完成」即可
- **统一设计 token 与共享组件**：页面栅格、卡片间距、动效时长集中定义，所有页面接入同一套
- **设置页与详情页修正**：配置目录路径按原样显示（不再多加空格）、XMPP 服务器行不再出现空行、连接状态卡不再重复显示 IP

### 构建与发布

- 构建链路升级到 Gradle 8.11.1 / AGP 8.9.1 / Kotlin 2.1.20 / JDK 17，Compose Material 3 升到 1.4.0
- `minSdk` 提升到 23（Android 6.0），`compileSdk` 提升到 36
- **Release 产物开始签名发布**，仓库内不保存私钥，CI 从 secrets 读取
- 新增发布工作流：打 `v*` 标签即自动构建、校验签名证书后发布 GitHub Release

### 其他

- 项目更名 **Pixel MiPushFramework**，中文名仍为「推送服务」；包名保持 `com.xiaomi.xmsf` 不变（接入方 SDK 的硬性要求，详见 README）
- 清理上游遗留的死代码与失效入口：移除旧的分步向导残留类、清理 80 余条无人引用的字符串资源、去掉 QQ 群与 Telegram 等已失效的联系方式

## 安装

下载 `xmsf-v1.0.0-normal-release.apk` 安装即可，装上后跟着向导走完权限设置。

- 优先使用 **normal** 版本
- 若你的系统（已知 COS）无法通过 bind 方式传递消息，改用 `xmsf-v1.0.0-vc105-release.apk`

> 升级提示：本版本的签名与此前上游官方包不同。如果你的设备上装的是其他来源的包，需要先卸载再安装，原有的注册列表与推送记录会被清除，各接入应用需要重新启动一次以完成注册。

## 已知问题

- 通知的时间戳沿用消息自身的时间，网络恢复后补收的旧消息会显示为旧时间
- 重连退避的上限为 5 分钟，极端情况下最长需要 5 分钟才会重新拨号
- 前台服务开关默认关闭

完整变更见 [提交历史](https://github.com/huaxianyan/PixelMiPushFramework/commits/master)。
