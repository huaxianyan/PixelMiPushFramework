## 新机器准备

1. 克隆完整仓库并获取标签，核对当前分支与工作区。构建版本推导需要 Git 历史和标签。
2. 按 [BUILDING](../BUILDING.md) 准备 JDK 17、共享 Android SDK 和仓库 Gradle Wrapper。路径改成本机实际位置，不沿用旧机器配置。
3. 按项目需要恢复 GitHub 与 SSH 访问。新机器的登录、网络和设备连接均未验证，旧环境的可用状态不能作为依据。
4. 本地配置 Android SDK 路径。机器约定可放在不入库的 `AGENTS.md`，并用 `.git/info/exclude` 忽略。
5. 开始任务前选定定向检查。普通 CI 无签名，发布另走 [RELEASING](RELEASING.md)，不为换机交接重复编译或安装。

## 签名与本地资料

Git 包含源码、公开交接和发布流程，不包含以下资料：

- 正式签名材料、属性文件和口令。既有独立备份的入口见旧机器本地 `AGENTS.md`。退出旧环境前，由材料持有人确认备份及恢复说明可用。本轮没有读取密钥内容，也没有在新机器恢复或验证签名。
- GitHub 本地登录、SSH 配置和设备连接信息。由使用者在新机器配置，不把凭据加入仓库。
- `.research/` 原始日志、研究样本和 Release 修改前备份，以及 `.workbuddy/memory/` 历史资料。这些目录被本地忽略，克隆无法取得。公开结论已写入交接记录，原始证据仍留在旧机器，尚未迁移。需要保留时单独确认安全存储和授权，原始消息、日志及图片须按私密资料处理。

新机器尚未恢复签名时，可以使用无签名构建检查代码。正式发布沿用既有 CI secrets 和长期证书，不能生成新签名冒充恢复成功。签名来源和构建参数见 BUILDING，不另维护一份。

## 持续开发约束

- 包名保持 `com.xiaomi.xmsf`。保留现有 SDK 3.7.9、schema 17 和真实推送行为，SDK 更换及数据库迁移分别实施与验收。
- 功能和修复使用独立主题分支，验收后合入 `master`。安装、清数据、卸载、换签和发布均须当前任务授权。
- 层级页面动效以 [Android 17 迁移文档](ANDROID17-MIGRATION.md) 的当前实现为准。保留现有导航架构，不恢复早期弹簧转场，也不将层级转场套到同级栏目。
- 当前首页保持移除注册标识后的布局，连接卡只表达连接状态，运行时长由服务侧记录。新增日志来源或升级日志库时核对统一脱敏出口。
- 构建参数以构建文件为唯一来源，检查和发布方法分别见 BUILDING 与 RELEASING。研究结论进入公开文档前须脱敏，静态产物检查与真实运行验收分别记录。
